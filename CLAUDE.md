# MetaJetCore — контекст проекта

Плагин для JetBrains IDE, который превращает одну сессию Claude Code в метаоркестратора:
она открывает рядом с собой вкладки с другими **полноценными** сессиями Claude Code и
управляет ими.

**Субагенты здесь не используются.** Каждый агент — отдельный процесс со своим контекстом.
Если предлагаешь решение через инструмент `Agent` — ты не понял задачу, перечитай
`docs/ARCHITECTURE.md` §1.1.

## Где что

- `docs/ARCHITECTURE.md` — техзадание. **Читай перед любыми правками дизайна.** Там же
  зафиксированы результаты проверок платформы, которые дорого перепроверять.
- `docs/PLUGIN-SPEC.md` — контракт MCP-инструментов.
- `plugin/` — Kotlin, IntelliJ Platform Gradle Plugin 2.x.
- `scripts/` — ручной режим без плагина.

## Проверенные факты, которые нельзя забывать

Проверены экспериментом на Claude Code 2.1.250, подробности в `ARCHITECTURE.md` §2:

- `CLAUDE_CODE_SESSION_NAME` — **работает**, задаёт имя сессии = адрес для `SendMessage`.
- `CLAUDE_CODE_AGENT` — пишется в реестр, но **роль не применяет**. Роль только через
  `--agent` / `--agents`.
- `CLAUDE_CODE_SESSION_ID` — **не работает**, id берётся из реестра после старта.
- `crossSessionInbound` принимает `accept` / `hold` / `refuse` (в одной из страниц
  документации указаны неверные значения).
- Реестр живых сессий: `~/.claude/sessions/<pid>.json`. Плагин его только читает.

## Правила для кода плагина

Главное требование к плагину — **не ломаться при апгрейде IDE**. Отсюда:

1. **Никаких сторонних библиотек.** Свой JSON (`util/Json.kt`), HTTP из JDK
   (`com.sun.net.httpserver`). Каждая зависимость — шанс конфликтнуть с платформой.
2. **Terminal API только через рефлексию** (`terminal/ReflectiveTerminalBackend.kt`).
   Он экспериментальный с 2025.3. При неудаче — деградация в ручной режим, никогда не
   исключение наружу.
3. **От терминала нужны ровно две операции**: создать вкладку и напечатать строку. Env,
   флаги и роль едут внутри печатаемой командной строки (`shell/ShellDialect.kt`).
   Не добавляй зависимостей от `ShellStartupOptions` и подобного.
4. **Контракт MCP-инструментов стабилен.** Это единственное, что видит оркестратор.
   Смена терминального API не должна менять сигнатуры в `mcp/McpTools.kt`.
5. **Из обработчиков MCP не должно вылетать исключений** — для оркестратора это выглядит
   как пропавший инструмент. Возвращай ошибку текстом.
6. Готовность сессии определяется появлением записи в реестре, **не таймером**: обёртка
   пользователя может стартовать сколько угодно.

## Сборка

```bash
cd plugin && ./gradlew buildPlugin
```

JDK 21. Wrapper не в репозитории — `gradle wrapper --gradle-version 8.10.2`, если его нет.

## Стиль

Комментарии объясняют **почему**, а не что. Особенно там, где решение выглядит странным:
рефлексия вместо импорта, свой JSON вместо библиотеки, env в командной строке вместо API.
Без такого комментария следующий читатель «упростит» код и сломает совместимость.
