# MetaJetCore — контекст проекта

Плагин для JetBrains IDE, который превращает одну сессию Claude Code в метаоркестратора:
она открывает рядом с собой вкладки с другими **полноценными** сессиями Claude Code и
управляет ими.

**Субагенты здесь не используются.** Каждый агент — отдельный процесс со своим контекстом.
Если предлагаешь решение через инструмент `Agent` — ты не понял задачу, перечитай
`docs/ARCHITECTURE.md` §1.1.

## Где что

- `docs/ARCHITECTURE.md` — техзадание. **Читай перед любыми правками дизайна.** Там же
  зафиксированы результаты проверок платформы, которые дорого перепроверять.
- `docs/PLUGIN-SPEC.md` — контракт MCP-инструментов.
- `plugin/` — Kotlin, IntelliJ Platform Gradle Plugin 2.x.
- `scripts/` — ручной режим без плагина.

## Проверенные факты, которые нельзя забывать

Проверены экспериментом на Claude Code 2.1.250, подробности в `ARCHITECTURE.md` §2:

- `CLAUDE_CODE_SESSION_NAME` — **работает**, задаёт имя сессии = адрес для `SendMessage`.
- `CLAUDE_CODE_AGENT` — пишется в реестр, но **роль не применяет**. Роль только через
  `--agent` / `--agents`.
- `CLAUDE_CODE_SESSION_ID` — **не работает**, id берётся из реестра после старта.
- `crossSessionInbound` принимает `accept` / `hold` / `refuse` (в одной из страниц
  документации указаны неверные значения).
- Реестр живых сессий: `~/.claude/sessions/<pid>.json`. Плагин его только читает.
- `ListAgents` печатает сессию как `слитие мастера [815818]` — хвост это **ref платформы, не
  часть имени**. Ref не выводится ни из pid, ни из sessionId, сопоставить по нему нечего.
  Оркестратор копирует строку дословно (так велит контракт инструмента), поэтому плагин
  снимает хвост сам — `AgentManager.canonicalName`. Пока не снимал, вкладка родителя не
  находилась и агент открывался в тулвиндоу, а `MJC_PARENT` уезжал несопоставимым.
- **Имена сессий не уникальны и меняются.** Три вкладки могут называться «слитие мастера»,
  `/rename` меняет имя посреди работы, а освободившееся имя занимает следующая сессия.
  Поэтому имя — не идентификатор: связь «агент → его оркестратор» задаётся `sessionId`
  (`MJC_PARENT_SESSION`), а `MJC_PARENT` с именем остаётся справочным. Всё, что всё-таки
  ищет сессию по имени, обязано перебирать все записи, а не брать первую.
- Определить `sessionId` родителя можно только через его процесс: запись реестра → pid
  `claude` → шелл вкладки (`TabResolver.resolve`). Если однозначно не вышло — переменной нет
  вовсе; связь наугад хуже отсутствия связи.

Проверено на 2026.3 (PY-263.7307) и Codex 0.166, подробности в `ARCHITECTURE.md` §2.7.2, §2.9:

- **Агент — процесс NON_SHELL-вкладки**: argv `<шелл> -l -i -c '[unset …; ]exec <команда>'`,
  `closeOnProcessTermination(true)`. Процесс умер — вкладка закрылась сама, без модального
  вопроса. Печати строки запуска в pty и хвостового `; exit` больше нет.
- **Терминал в редакторе — `TerminalViewVirtualFile.getTab()`.** `getTerminalView()` нет ни в
  262, ни в 263. `Content.manager` для побывавших в редакторе вкладок врёт — открытость
  проверяем по спискам платформы.
- **Codex:** доверие — `-c 'projects={"<путь>"={trust_level="trusted"}}'` (dotted-ключ ломается
  на точках в пути); `--disable hooks` против вопроса «Review hooks»; роль — профиль
  `-p mjc-<role>`; без первого сообщения сессии нет, поэтому задача в argv через `"$MJC_TASK"`;
  ответы — `task_complete.last_agent_message` в `~/.codex/sessions/**/rollout-*.jsonl`;
  доставка — `codex queue --thread <id> --message`; `/quit` в терминале IDE не работает —
  закрываем SIGTERM дереву процессов.
- Роли без `tools:` и скилл без `disallowed-tools` — намеренно: белый список отрезал `Skill` и
  MCP IDE. Ограничения словами. Не возвращать.

## Правила для кода плагина

Главное требование к плагину — **не ломаться при апгрейде IDE**. Отсюда:

1. **Никаких сторонних библиотек.** Свой JSON (`util/Json.kt`), HTTP из JDK
   (`com.sun.net.httpserver`). Каждая зависимость — шанс конфликтнуть с платформой.
2. **Terminal API только через рефлексию** (`terminal/Terminal.kt`). Классы нового терминала
   помечены `@Experimental`, поэтому прямой вызов при смене сигнатуры дал бы
   `NoSuchMethodError` в рантайме. Рефлексия даёт null и деградацию в ручной режим —
   исключение наружу не летит никогда.
3. **Целевая платформа — 2026.3+, переработанный терминал.** Нижняя граница поднята с 2026.2
   ради API агентов терминала (`TerminalAgent`, список харнесов IDE) и NON_SHELL-вкладок. Поддержки JediTerm-терминала
   (`ShellTerminalWidget`, `createLocalShellWidget`) в коде нет и заводить её заново не надо:
   в 2026.2 первый путь бросает, а второй отдаёт виджет, в который нечем печатать.
4. **Окружение агента едет через API вкладки** (`envVariables` билдера), не в командной
   строке. В строке — только роль и режим прав: их иначе не передать. Диалект шелла нужен
   ровно для одной операции — снять унаследованные переменные (`shell/ShellDialect.kt`), и
   берётся он по фактическому процессу вкладки, а не по настройкам.
5. **Содержательный канал один — `SendMessage`.** Плагин печатает в терминал только
   управляющие команды (`/exit`, `/clear`). `brief_agent` — аварийный канал. Исключение —
   Codex, у которого `SendMessage` нет: лента сессии + `codex queue`
   (`await_messages` / `send_to_agent`).
6. **Контракт MCP-инструментов стабилен.** Это единственное, что видит оркестратор.
   Смена терминального API не должна менять сигнатуры в `mcp/McpTools.kt`.
7. **Из обработчиков MCP не должно вылетать исключений** — для оркестратора это выглядит
   как пропавший инструмент. Возвращай ошибку текстом.
8. Готовность сессии определяется появлением записи в реестре, **не таймером**: обёртка
   пользователя может стартовать сколько угодно.
9. `~/.claude.json` принадлежит Claude Code. Читаем-меняем-пишем целиком, поэтому: числа
   сохраняем литералами, перед подменой перечитываем файл и при чужой правке начинаем заново.

## Сборка

```bash
cd plugin && ./gradlew buildPlugin
```

JDK 21 (подходит JBR из установленной IDE). Gradle-JVM не читает `HTTPS_PROXY` — прокси
передавать `-Dhttps.proxyHost/-Dhttps.proxyPort` (и `http.*`). Источник платформы —
`MJC_LOCAL_IDE=<путь к IDE 263+>`.

**Перед релизом — `verifyPlugin` и против самой старой сборки 263, что есть под рукой:**
`MJC_VERIFY_IDES=<путь>[:<путь>…]`. Собираем против новой, а ломается на старой: 0.5.0 против
263.7307 была «Compatible», а в PhpStorm 263.6949 падала `NoSuchFieldError` на
`FileEditorManager.Companion` — класс переписали на Kotlin между сборками, и плагин не видел
терминалов в редакторе. Отсюда же правило в коде: менеджеры платформы — через
`project.getService(...)` (`terminal/Editors.kt`), а не статическим `getInstance`.
`MJC_LOCAL_IDE` для этого не подходит: он меняет платформу компиляции и пересобирает архив.

Песочница (`runIde`) — бесплатная/EAP IDE (PyCharm 2026.3 RC): платная встаёт на диалоге
лицензии, и MCP-сервер не отвечает. Тесты по одному прогону за раз; они ставят скилл, роли и
профили Codex в настоящие `~/.claude` и `~/.codex`.

## Стиль

Комментарии объясняют **почему**, а не что. Особенно там, где решение выглядит странным:
рефлексия вместо импорта, свой JSON вместо библиотеки, env в командной строке вместо API.
Без такого комментария следующий читатель «упростит» код и сломает совместимость.
