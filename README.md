# MetaJetCore

Метаоркестратор Claude Code внутри JetBrains IDE.

Одна сессия Claude Code — оркестратор — открывает рядом с собой вкладки с другими
**полноценными** сессиями (планировщик, имплементер, ресерчер, ревьювер), раздаёт им задачи,
отвечает на их вопросы вместо разработчика и сводит результат. Разработчик читает и пишет
только в одну вкладку. Агентом может быть Claude Code или Codex — по выбору для каждой роли.
Работает и поверх `/tempo`: его субагенты запускаются полноценными сессиями.

Субагенты не используются: каждый агент — отдельный процесс со своим контекстом, который
сохраняется между итерациями. Именно это делает схему дешевле субагентов, которые при каждом
запуске ресерчат заново то, что уже было выяснено.

```
┌─ IDE ───────────────────────────────────────────────┐
│  mjc-orc  (ты пишешь сюда)  │  mjc-impl-be          │
│         │ MCP               │  mjc-rsrch            │
│         ▼                   │                       │
│   MetaJetCore plugin ───────┘  открывает вкладки    │
└─────────────────────────────────────────────────────┘
       mjc-orc ⇄ mjc-impl-be — штатный cross-session messaging
```

## Развернуть с нуля

Нужно: JetBrains IDE **2026.3+** (переработанный терминал и API агентов терминала), Claude Code
2.1.234+, JDK 21 (или Gradle сам его скачает). Для ролей на Codex — Codex 0.166+.

```bash
# 1. Собрать плагин
cd plugin
./gradlew buildPlugin          # zip окажется в plugin/build/distributions/

# 2. Установить
#    Settings | Plugins | ⚙ | Install Plugin from Disk… → выбрать этот zip
#    Перезапустить IDE

# 3. Ничего. Плагин сам прописывает себя в ~/.claude.json для этого проекта.

# 4. Проверить, что всё нашлось
#    Tools | MetaJetCore | Diagnostics
```

### Настройка под свою команду запуска

Если `claude` вызывается через обёртку, укажите её в
`Settings | Tools | MetaJetCore | Команда запуска`.

Проверьте, пробрасывает ли обёртка аргументы — от этого зависит, применятся ли роль и
режим прав вообще:

```bash
MJC_LAUNCH=<ваша-обёртка> ./scripts/check-wrapper.sh
```

Не пробрасывает — почините одной строкой: `exec claude "$@"`. Без этого флаги `--agent` и
`--permission-mode` до claude не дойдут, и агент стартует безролевым в manual mode.

### Роли на Codex

`Settings | Tools | MetaJetCore | Харнесы ролей` — для каждой роли Claude Code или Codex и
модель. Оркестратор всегда Claude Code. Роль Codex получает профилем
`~/.codex/mjc-<role>.config.toml`, плагин пишет его сам; каталог проекта помечается
доверенным только на запуск, `~/.codex/config.toml` не меняется.

## Использование

В любой сессии Claude Code вызовите `/orchestrate` — сессия становится оркестратором.
Вкладку оркестратора плагин находит сам, сопоставляя её с сессией по дереву процессов, так что
открыть её можно и руками.

Но лучше открыть действием **Tools | MetaJetCore | New Orchestrator Here**: оно сразу
переносит вкладку в editor area, и только тогда агенты появляются рядом с оркестратором.
У вкладки в терминальном тулвиндоу «рядом» просто не существует.

Скилл ставится плагином в `~/.claude/skills/orchestrate/` автоматически, поэтому доступен
во всех проектах.

Дальше разговаривайте только с оркестратором: он сам заведёт нужных агентов. С `/tempo`:
вызовите `/orchestrate`, затем `/tempo` — планировщик, имплементеры и проверяющие tempo станут
отдельными вкладками, правки после гейтов пойдут тем же агентам.

## Работа без плагина

Вкладку придётся открыть самому, всё остальное так же. Роли берутся из `~/.claude/agents/`,
куда их кладёт плагин, поэтому один раз его всё-таки надо запустить:

```bash
./scripts/spawn-agent.sh implementer mjc-impl-be
```

## Перенос в другой проект

С установленным плагином — **переносить нечего**. И скилл оркестратора, и определения ролей
живут в пользовательском скоупе (`~/.claude/`), плагин их ставит сам. В целевом проекте нужен
один ключ:

```json
{ "crossSessionInbound": "accept" }
```

Режим прав через настройки проекта задать нельзя — Claude Code игнорирует repo-level
`permissions.defaultMode`, поэтому его передаёт плагин флагом `--permission-mode`.

Подробности и подводные камни — `docs/ARCHITECTURE.md` §12.
