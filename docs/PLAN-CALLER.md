# План: родитель агента — по вызывающей сессии, рядом с ним — и во вкладке AIR

Два симптома, одна причина: плагин узнаёт оркестратора по **имени** из `parent` и ищет его
вкладку только среди **терминалов** IDE.

1. **Связь теряется после `/rename`** (сообщила OctoDash, 12.11): оркестратор продолжает
   передавать старое имя, в реестре его нет — `MJC_PARENT_SESSION` не ставится.
2. **Агент открывается рядом с активной вкладкой, а не с родителем.** Лог 12.11: «вкладку для
   'modules-bc' сопоставить не удалось» — на каждом спавне, и до переименования тоже.
   Оркестратор живёт во вкладке **AIR** (`plugins/air-plugin`, «Agent Threads»), а не в
   терминале: `diagnostics` видит 0 терминалов при открытой сессии. Родитель не найден —
   агент уходит в текущее окно редактора.

## Проверено

- MCP-сервер — HTTP внутри IDE, общий на все сессии проекта; дерево процессов от него не
  ведёт к вызывающему. Но во время вызова `lsof -iTCP:<порт клиента>` показывает соединение,
  клиентская сторона которого — сам процесс `claude` (pid 66324 = `~/.claude/sessions/66324.json`).
  Порт клиента сервер видит как `HttpExchange.remoteAddress`.
- Вкладка AIR — файл `com.intellij.air.thread.view.AgentThreadViewContentFile`
  (`agent-thread-view://…`), у него `getThreadId()` = `sessionId` Claude (workspace.xml:
  `threadIdentity="claude:145c9b27-…" threadId="145c9b27-…"`). AIR внутри построен на том же
  `TerminalView`, но достаём не его — `threadId` проще и надёжнее.
- AIR есть в PhpStorm 263.8054, в PyCharm 2026.3 RC его нет.

## Решения

1. **Вызывающая сессия — по TCP-соединению запроса.** `McpServerService` передаёт в
   `tools/call` порт клиента; `spawn_agent` по нему находит pid (`lsof`; Linux без lsof — `ss`;
   Windows — `netstat -ano`), от pid вверх по предкам — запись реестра. Не вышло — как раньше,
   по имени. Связь наугад по-прежнему хуже отсутствия связи: несколько разных записей — null.
2. **`MJC_PARENT_SESSION` — `sessionId` вызывающей сессии, `MJC_PARENT` — её текущее имя** из
   реестра. Аргумент `parent` остаётся запасным путём и для размещения, если вызывающего не
   определили.
3. **Вкладка родителя:** терминал по дереву процессов, как раньше; иначе — открытый файл AIR
   с `threadId == sessionId` родителя, и агент открывается в окне редактора, где лежит этот
   файл. AIR — внутренний плагин, только рефлексия по имени интерфейса и метода.
4. Контракт MCP-инструментов не меняется. `diagnostics` показывает число вкладок AIR.

## Тесты

- Юнит: разбор вывода `lsof` / `ss` / `netstat`; запись реестра по pid и по предку.
- Живой юнит: дочерний процесс подключается к сокету, плагин находит его pid по порту.
- Платформенный: подставной файл с интерфейсом AIR (в PyCharm RC настоящего нет) —
  находится по `threadId`.
- Живая проверка в PhpStorm: спавн из AIR-вкладки после `/rename` — агент рядом, переменная есть.

## Риски

- `/clear` в Claude меняет `sessionId`; меняется ли `threadId` у файла AIR — не проверено.
  Худший исход — агент в текущем окне, как сейчас.
- Клиент через прокси к localhost — по порту найдётся прокси, не сессия; его нет в реестре,
  срабатывает запасной путь.
