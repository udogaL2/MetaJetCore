# MetaJetCore plugin — контракт

Дополнение к `docs/ARCHITECTURE.md`. Здесь только то, что нужно для реализации и что
проверяется тестами.

Плагин для JetBrains IDE **2026.2+**, Kotlin, JDK 21. Поднимает локальный MCP-сервер, к
которому подключается сессия-оркестратор.

Каждый агент — **полноценная отдельная сессия Claude Code** в своей вкладке. Субагенты
(инструмент `Agent`) в схеме не участвуют.

```xml
<depends>com.intellij.modules.platform</depends>
<dependencies>
    <plugin id="org.jetbrains.plugins.terminal"/>
    <module name="intellij.terminal.frontend"/>
</dependencies>
```

Зависимость на модуль обязательна: API переработанного терминала живёт в нём, и без записи в
дескрипторе classloader плагина его не видит. Сами вызовы всё равно идут рефлексией — чтобы
смена сигнатур давала ручной режим, а не `NoSuchMethodError`.

---

## 1. MCP-инструменты

Всё возвращается **текстом**: оркестратор читает результат как обычный ответ инструмента, а
не разбирает JSON. Исключений из этого правила нет, ошибки тоже текст (с `isError`).

### `spawn_agent`

```
spawn_agent(
    role:    "implementer" | "researcher" | "reviewer" | "orchestrator",
    parent:  string,   # имя ТВОЕЙ сессии (первая строка ListAgents)
    task:    string,   # брифинг; инструмент его НЕ доставляет, см. ниже
    name?:   string,   # по умолчанию <prefix>-<роль>[-<домен>]
    model?:  string,   # по умолчанию из таблицы ролей
    domain?: string,   # be / fe / sec / arch — различает агентов одной роли
) -> текст: имя, sessionId, pid + напоминание отправить задачу через SendMessage
```

Последовательность:

1. Сгенерировать имя и проверить, что оно не занято живой сессией.
2. Открыть вкладку терминала (`TerminalToolWindowTabsManager.createTabBuilder()`), передав
   окружение через `envVariables`:
   ```
   CLAUDE_CODE_SESSION_NAME = <name>      # адрес для SendMessage
   ANTHROPIC_MODEL          = <model>
   CLAUDE_CODE_AGENT        = <role>      # только метка в реестре, роль НЕ задаёт
   MJC_REPORTS_DIR          = <каталог отчётов вне репозитория>
   MJC_PARENT               = <parent>    # имя оркестратора; ключа нет, если родителя нет
   ```
3. Если вкладка родителя живёт в editor area — открыть новую рядом с ней
   (`TerminalInEditorSupport.openInEditor`), иначе оставить в тулвиндоу.
4. Дождаться, пока `sessionState` вкладки станет `Running`.
5. Напечатать команду запуска — **только ASCII и только то, что нельзя задать окружением**:
   ```
   [снятие унаследованных маркеров; ]<launchCommand> --agent mjc-<role> --permission-mode auto
   ```
6. Дождаться появления `~/.claude/sessions/<pid>.json` с `name == <name>`; взять оттуда
   `pid`, `sessionId` и **фактическое имя** (при коллизии платформа переименует сессию).
7. Вернуть оркестратору имя и текст задачи с указанием отправить её через `SendMessage`.

**Задачу инструмент не доставляет намеренно.** Содержательный канал один — межсессионные
сообщения: они адресные, попадают в очередь агента и не зависят от того, что сейчас на экране
вкладки. Печать в TUI осталась управляющим командам и аварийному `brief_agent`.

Ошибки — текстом: имя занято, терминал недоступен, шелл не поднялся, сессия не появилась в
реестре. В последних трёх случаях возвращается готовая команда для ручного запуска.

### `list_agents() -> текст`

Живые сессии в директории проекта: имя, роль (из `agent` реестра или из своей карты), модель,
статус, pid, пометка «вкладка не под управлением плагина». Записи мёртвых процессов
отфильтрованы: файл в реестре остаётся после падения сессии.

### `brief_agent(name, text) -> текст`

Впечатывает текст во вкладку как ввод пользователя (bracketed paste + Enter). **Аварийный
канал**: обычная переписка — `SendMessage`.

### `reset_agent(name) -> текст`

Печатает `/clear`. Новую задачу оркестратор отправляет сам. Применяется при переходе между
этапами; внутри этапа сохранённый контекст — главная экономия схемы.

### `close_agent(name) -> текст`

`/exit` → ждать исчезновения записи из реестра → закрыть вкладку. Процесс никогда не убиваем:
останется запись в реестре и мёртвый пайп, и `ListAgents` будет показывать призрака.

### `focus_agent(name) -> текст`

Показать вкладку разработчику.

### `read_tab(name) -> текст`

Хвост экрана вкладки (последние ~4000 символов). Для случая «агент поднялся, но молчит»:
увидеть, на каком интерактивном вопросе он встал, можно только так.

### `diagnostics() -> текст`

Что разрешилось из терминального API, какие переменные вычищаются, сколько вкладок под
управлением, пример команды для ручного режима.

## 2. Настройки плагина

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `launchCommand` | `claude` | обёртка пользователя; обязана пробрасывать `"$@"` |
| `permissionMode` | `auto` | флаг `--permission-mode`; пусто — не добавлять |
| `namePrefix` | аббревиатура проекта | `MetaJetCore` → `mjc` |
| `readyTimeoutSeconds` | `45` | ожидание записи в реестре; держим ниже MCP-таймаута |
| `stripApiKeys` | `true` | снимать `ANTHROPIC_*` |
| `stripInheritedClaudeMarkers` | `true` | снимать `CLAUDE*` |
| `extraEnvRaw` | пусто | дополнительные переменные, `KEY=VALUE` построчно |
| `mcpPort` | `0` | 0 — вывести из пути проекта, чтобы порт был стабильным |

Диалект шелла настройкой не задаётся: он определяется по фактическому процессу вкладки
(`startupOptionsDeferred.shellCommand`).

---

## 3. Карта вкладок

1. **Основной путь.** Вкладки, созданные плагином (`spawn_agent`, «New Orchestrator Here»),
   лежат в карте `имя → вкладка`.
2. **Запасной.** Для сессий, запущенных руками: `startupOptionsDeferred.pid` даёт pid шелла
   вкладки, реестр — pid процесса `claude`; если шелл среди предков claude, сессия живёт в
   этой вкладке. Если и это не сработало — сравнение с заголовком вкладки.

Разместить агента рядом можно только с тем родителем, который живёт в editor area. Поэтому
действие **New Orchestrator Here** сразу переносит вкладку туда: у запущенной руками вкладки
в тулвиндоу «рядом» не существует.

## 4. Что осталось нереализованным

- `restart_agent` (close + spawn с теми же параметрами).
- Наблюдение за реестром: сейчас плагин опрашивает его только внутри операций, а событий
  «агент умер» / «агент ждёт ввода» не отслеживает.
- Восстановление раскладки после рестарта IDE.
