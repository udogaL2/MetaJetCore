# MetaJetCore plugin

Плагин для JetBrains IDE 2025.1+. Открывает рядом с сессией-оркестратором вкладки с другими
полноценными сессиями Claude Code и управляет их жизненным циклом.

Дизайн — `../docs/ARCHITECTURE.md`, контракт инструментов — `../docs/PLUGIN-SPEC.md`.

## Сборка

Нужен JDK 21 (подойдёт JBR из любой IDE 2025+).

```bash
cd plugin
./gradlew buildPlugin        # zip в build/distributions/
./gradlew runIde             # песочница с плагином
./gradlew verifyPlugin       # проверка совместимости с рекомендованными IDE
```

Gradle wrapper лежит в репозитории, отдельно ставить Gradle не нужно.

## Установка

`Settings | Plugins | ⚙ | Install Plugin from Disk…` и указать zip из `build/distributions/`.

## Подключение оркестратора

1. `Tools | MetaJetCore | Copy MCP Config Command`
2. Вставить полученную команду в терминал (это `claude mcp add --transport http …`)
3. В сессии, которая станет оркестратором, вызвать `/orchestrate`

Скилл `orchestrate` плагин ставит сам в `~/.claude/skills/orchestrate/` при старте IDE и
обновляет при каждом запуске: он описывает инструменты плагина, поэтому их версии обязаны
совпадать.

## Как это устроено, коротко

**Роль оркестратора — скилл, роли агентов — флаг.** Обычные сессии Claude Code остаются
обычными; оркестратором сессия становится по вызову `/orchestrate`, в том числе посреди
разговора, когда контекст задачи уже набран. Дочерние агенты получают роль флагом
`--agent mjc-<role>`; определения плагин раскладывает файлами в `~/.claude/agents/` при старте
IDE, и claude читает их сам как UTF-8. Ограничение набора инструментов при этом жёсткое — агенты
работают в ненаблюдаемых вкладках, там гарантия нужна настоящая.

**Плагин печатает в терминал только ASCII и только команду запуска.** Переменные окружения и
флаги едут внутри набираемой строки (`shell/ShellDialect.kt`); текст роли — файлами, задача
агенту — через `SendMessage`. Поэтому от терминального API нужны ровно две операции: создать
вкладку и напечатать строку. Почему именно так — `../docs/ARCHITECTURE.md` §2.6.

**Готовность определяется по реестру сессий**, а не по таймеру: `~/.claude/sessions/<pid>.json`
появляется тогда, когда `claude` поднялся и забиндил inbox-сокет, то есть готов и к вводу,
и к межсессионным сообщениям.

## Что сделано ради устойчивости к апгрейдам IDE

| Решение | Зачем |
|---|---|
| Terminal API только через рефлексию, три поколения | API помечен экспериментальным с 2025.3; при неудаче — деградация в ручной режим, а не падение |
| `<depends optional="true">` на плагин терминала | плагин грузится даже если терминал отключён |
| Нет `untilBuild` | плагин не отключается при апгрейде IDE; безопасно только благодаря рефлексии |
| Свой JSON вместо библиотеки | нечему конфликтовать с версией из платформы |
| `com.sun.net.httpserver` вместо HTTP платформы | JDK не меняется, внутренние API платформы меняются |
| Env через командную строку, не через API | убирает зависимость от `ShellStartupOptions` и его эволюции |

Если что-то всё-таки сломается — `Tools | MetaJetCore | Diagnostics` покажет, какое поколение
терминального API разрешилось и разрешилось ли вообще.

## Terminal API: что там на самом деле

Проверено `javap` по jar-ам двух платформ — IDEA Community 2025.1 (то, против чего собираем)
и PyCharm Community 2026.1 (рабочая IDE). **Наборы совпадают полностью:**

| Класс / метод | 2025.1 | 2026.1 |
|---|---|---|
| `TerminalToolWindowManager.getInstance(Project)` | есть | есть |
| `createLocalShellWidget(String, String[, boolean[, boolean]])` → `ShellTerminalWidget` | есть, 3 арности | есть, 3 арности |
| `createShellWidget(String, String, boolean, boolean)` → `TerminalWidget` | есть | есть |
| `ShellTerminalWidget.executeCommand(String)` | есть | есть |
| `ShellTerminalWidget.getProcessTtyConnector()` | есть | есть |
| `TerminalOptionsProvider.getInstance().getShellPath()` | есть | есть |
| `TerminalToolWindowTabsManager` | **нет** | **нет** |

Отсюда два следствия:

1. **`createLocalShellWidget` предпочтительнее `createShellWidget`.** Первый возвращает
   конкретный `ShellTerminalWidget` с `executeCommand(String)`; второй — интерфейс
   `TerminalWidget`, в который печатать нечем.
2. **Ветка G3 (`TerminalToolWindowTabsManager`) — задел на будущее.** Этот класс описан в
   SDK-документации, но в поставке его нет ни в 2025.1, ни в 2026.1. Ветка просто не
   срабатывает и стоит первой на случай, когда он появится.

Практический вывод: прогон в песочнице 2025.1 проверяет **ровно тот же путь кода**, который
выполнится в рабочей IDE 2026.1.

## Статус

Собирается, все тесты проходят, **проверен живым прогоном в песочнице IDE**: плагин
загружается, MCP-сервер отвечает, вкладка открывается, агент поднимается, регистрируется в
`~/.claude/sessions`, отвечает на `SendMessage` и корректно закрывается через `close_agent`.

Что живой прогон вскрыл и что из этого следует — `../docs/ARCHITECTURE.md` §2.6. Коротко:
терминал IDE запускает свой шелл (у нас оказался Git Bash, а не cmd), PowerShell не передаёт
нативному exe аргумент с кавычками и пробелами, терминал пишет в pty в кодировке JVM, а
наследуемые маркеры `CLAUDE_*` мешают агенту зарегистрироваться. Отсюда главное правило: в
терминал печатается только ASCII и только команда запуска.

Не проверено:

- сборка и прогон на Linux (целевая ОС) — проверялось на native Windows;
- открытие вкладки **рядом с родителем** через сплит editor area: сейчас вкладка создаётся
  в Terminal tool window, `nearTab` пока не используется;
- `reset_agent` и `restart_agent` живым прогоном не гонялись.
